🔧 Les 3 Techniques d'Optimisation Principales

1️⃣ Manipulation Directe des Registres GPIO

Méthode Classique (LENTE)

// Sélection du canal 5 du multiplexeur (0101 en binaire) digitalWrite(muxch1, HIGH); // S0 = 1 → ~5µs digitalWrite(muxch2, LOW); // S1 = 0 → ~5µs digitalWrite(muxch3, HIGH); // S2 = 1 → ~5µs digitalWrite(muxch4, LOW); // S3 = 0 → ~5µs // TOTAL: ~20µs pour 4 pins
❌ Problèmes de digitalWrite() :
  • Appel de fonction avec vérifications de sécurité
  • Recherche du pin dans une table de mapping
  • Vérification si le pin est configuré en OUTPUT
  • 4 appels séparés = 4× l'overhead

Méthode ElBourak (RAPIDE)

// Précalcul au démarrage (1 seule fois) muxStates[5] = (1 << muxch1) | (1 << muxch3); // État pour canal 5 // À chaque lecture (ultra-rapide) REG_WRITE(GPIO_OUT_W1TC_REG, muxAllMask); // Efface tous les pins → ~0.2µs REG_WRITE(GPIO_OUT_W1TS_REG, muxStates[5]); // Active S0 et S2 → ~0.2µs // TOTAL: ~0.5µs pour 4 pins
✅ Avantages des registres directs :
  • Écriture directe dans la mémoire matérielle
  • Pas de vérifications ni d'overhead
  • 1 seule opération pour plusieurs pins
  • 40x plus rapide que digitalWrite()

2️⃣ Accès Direct à l'ADC (Analog-to-Digital Converter)

Méthode Classique (LENTE)

// Lecture analogique standard Arduino int value = analogRead(36); // ~100-250µs // Ce que fait analogRead() en interne : // 1. Vérifie si le pin existe // 2. Configure l'ADC (à chaque fois!) // 3. Fait la conversion // 4. Attend la fin de conversion // 5. Lit le résultat // 6. Retourne la valeur
❌ Problèmes d'analogRead() :
  • Reconfigure l'ADC à chaque lecture (inutile!)
  • Fait des vérifications de sécurité répétées
  • Utilise des délais de sécurité excessifs
  • Overhead de fonction = ~100µs par lecture

Méthode ElBourak (RAPIDE)

// Configuration 1 SEULE FOIS au démarrage adc1_config_width(ADC_WIDTH_BIT_12); // 12-bit (0-4095) adc1_config_channel_atten(ADC1_CHANNEL_0, ADC_ATTEN_DB_12); // Lecture ultra-rapide (répétée des milliers de fois) int value = adc1_get_raw(ADC1_CHANNEL_0); // ~3-12µs // Lecture directe du convertisseur, pas de configuration!
✅ Avantages de l'ADC direct :
  • Configuration faite 1 fois au lieu de milliers
  • Accès direct au matériel ADC
  • Pas d'overhead de fonction
  • 33x plus rapide qu'analogRead()

Mapping GPIO → Canaux ADC ESP32

// L'ESP32 a des pins ADC spécifiques : GPIO36 → ADC1_CHANNEL_0 GPIO39 → ADC1_CHANNEL_3 GPIO34 → ADC1_CHANNEL_6 GPIO35 → ADC1_CHANNEL_7 GPIO32 → ADC1_CHANNEL_4 GPIO33 → ADC1_CHANNEL_5 // Utiliser UNIQUEMENT ces pins pour l'ADC!

3️⃣ Remplacement Division par Multiplication + Décalage

Méthode Classique (LENTE)

// Calibration d'une valeur brute (0-4095) vers 0-1000 int range = maxValue - minValue; // Ex: 3000 int calibrated = (raw - minValue) * 1000 / range; // La division (/) prend environ 40-50 cycles CPU! // Sur ESP32 à 240MHz: 1 cycle = 4.2ns // Division = ~200ns
❌ Problème de la division :
  • Opération lente sur microcontrôleur (40-50 cycles)
  • Répétée 16 fois (1 par capteur) à chaque lecture PID
  • Total: ~3200ns perdus par lecture complète

Méthode ElBourak (RAPIDE)

// ÉTAPE 1: Précalcul au moment de la calibration (1 fois) int range = maxValue - minValue; invRange = 1024000 / range; // Ex: si range=3000, invRange=341 // ÉTAPE 2: Utilisation lors des lectures (milliers de fois) int calibrated = ((raw - minValue) * invRange) >> 10; // Multiplication (*) = ~3 cycles CPU // Décalage (>>) = ~1 cycle CPU // Total = ~20ns au lieu de ~200ns
✅ Pourquoi ça marche :
  • x / range = (x * (1024/range)) / 1024
  • / 1024 = >> 10 (décalage binaire)
  • On précalcule 1024000/range pour avoir la bonne échelle
  • 8-10x plus rapide que la division!

Exemple Numérique Détaillé

// Données de calibration minValue = 500 maxValue = 3500 range = 3000 // Précalcul invRange = 1024000 / 3000 = 341 // Lecture brute raw = 2000 // MÉTHODE CLASSIQUE: calibrated = (2000 - 500) * 1000 / 3000 calibrated = 1500 * 1000 / 3000 calibrated = 1500000 / 3000 ← DIVISION LENTE (40 cycles) calibrated = 500 // MÉTHODE ELBOURAK: calibrated = (2000 - 500) * 341 >> 10 calibrated = 1500 * 341 >> 10 calibrated = 511500 >> 10 ← DÉCALAGE RAPIDE (1 cycle) calibrated = 499 ← Résultat quasi identique!
